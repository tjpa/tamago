# Tamago — dispatch & invoicing (spec v0.1)

Small, product-shaped app in the logistics/field-service domain: quote → dispatch → deliver → invoice.
Purpose: a defensible, deployable demonstration of Python backend, React/TypeScript, PostgreSQL,
and an event-driven (DB-backed queue + worker) architecture, built with an AI-assisted workflow.

## Stack
- Backend: FastAPI, SQLAlchemy 2 + Alembic, PostgreSQL 16, pytest
- Worker: separate process, polls `tasks` table, atomic claim via `FOR UPDATE SKIP LOCKED`
- Frontend: React + TypeScript + Vite, TanStack Query, Tailwind v4 + shadcn/ui
- Design: screens designed in Pencil (`tamago.pen`, shadcn design system) before frontend code; frontend built from those screens
- Lint: `@shadcn/lint` (Oxlint) for design-system rules, set up per its SETUP.md; ruff for Python
- Infra: Docker Compose (api, worker, db, web). S3-compatible storage via adobe/s3mock locally (MinIO no longer publishes Docker images); same boto3 code targets AWS S3.
- CI: GitHub Actions (lint, tests)

## Domain
- Job: customer, pickup/dropoff, description, price. Status: created → dispatched → in_transit → completed → invoiced
- Driver / Vehicle: assignable to jobs
- Invoice: generated by worker on completion; PDF stored in object storage
- Task (queue): id, type, payload(json), status(pending|running|done|failed), attempts, max_attempts, run_after, locked_at, last_error

## Event-driven behaviour
- Status transitions write a task in the same DB transaction (transactional outbox pattern)
- Worker claims with SKIP LOCKED, retries with backoff, moves to `failed` after max_attempts
- Handlers are idempotent (invoice generation keyed on job_id)

## Phases (each gated on review)
1. Backend core: models, migrations, job/driver API, tests
2. Queue + worker: outbox, claim/retry, invoice handler, tests
3. Screens in Pencil: job board, create job, job detail/status timeline, drivers, invoices — composed from the shadcn components in the .pen file
4. Frontend: implement the screens in React/TS/shadcn; install `@shadcn/lint` (register plugin only, then agree rules)
5. Compose + S3 mock, CI (ruff, pytest, oxlint, tsc), README with architecture notes
6. (Optional) AWS deploy notes/Terraform-lite

## Design (Phase 3, approved via Pencil: `docs/design/tamago.pen`, PNGs in `docs/design/screens/`)
- Dark theme, shadcn design system (Inter), left sidebar app shell (Jobs, Drivers & vehicles, Invoices)
- Screens: Jobs board (Kanban by status) / Jobs table (toggle), Job detail (status timeline, assignment, invoice), Drivers & vehicles, Invoices, New job dialog, Dispatch dialog, states (loading/empty/error/success)
- Status colours are design tokens (`--status-<state>` and `--status-<state>-bg`, light + dark) added to the .pen file; map to CSS variables in the frontend
- The primary action on job detail is contextual: Dispatch (created) → Start (dispatched) → Mark completed (in_transit); `invoiced` is set by the worker, never by the UI

## Non-goals
Auth beyond a simple API key, maps/routing, Kafka/DynamoDB/Kinesis.
